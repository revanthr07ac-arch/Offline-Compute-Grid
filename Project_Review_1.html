OFFLINE COMPUTE GRID:
LOCATION-AWARE TASK OFFLOADING IN TWO-TIERED MOBILE CLOUD ENVIRONMENTS

V SEMESTER COMPREHENSIVE PROJECT REVIEW

1. Abstract

Mobile Cloud Computing (MCC) is rapidly emerging as a primary ubiquitous computing platform, enabling mobile devices to overcome inherent resource limitations—such as battery life, storage capacity, and processing power—by offloading data-intensive computational tasks to resource-rich environments. The "Offline Compute Grid" project proposes and implements a comprehensive management dashboard designed for a two-tiered mobile cloud computing architecture. This architecture bridges the gap between resource-poor mobile devices and high-latency public clouds by introducing an intermediate "local cloudlet" accessible via Wi-Fi.

The core objective of this project is to implement an online, location-aware offloading system that fairly shares the use of the local cloudlet among multiple heterogeneous mobile devices. Instead of relying on rigid, offline scheduling, the system utilizes a Node.js-based orchestration backend to dynamically evaluate real-time parameters such as device residual energy, Wi-Fi access point bandwidth capacities, and strict Service Level Agreements (SLAs). The project culminates in a highly responsive React.js Single Page Application (SPA) dashboard that provides network administrators with real-time visualization of task offloading bipartite-matching algorithms, ensuring that mobile devices extend their operational lifetimes by consuming a fair, proportional amount of energy across the grid.

2. Introduction

With the relentless technological advancement of wireless portable devices, modern society has become heavily dependent on smartphones and tablets for increasingly complex applications. Applications such as augmented reality, high-definition video processing, and real-time machine learning inference require significant computational and storage resources that most mobile devices simply cannot meet due to strict physical constraints on CPU speed and battery capacity. Mobile Cloud Computing (MCC) addresses these demands by shifting the heavy lifting from the mobile device to the cloud. However, traditional MCC relies on remote public clouds (e.g., Amazon EC2, Microsoft Azure), which must be accessed via 3G/4G cellular networks. Cellular transmission suffers from high latency, slow data transfer rates, and massive energy consumption on the mobile device's radio interface, often negating the benefits of offloading.

To resolve this, the "Offline Compute Grid" implements a two-tiered architecture that introduces a "local cloudlet"—a cluster of localized computers accessible via high-speed, low-energy Wi-Fi connections. Because mobile users are dynamic and move unpredictably through different Wi-Fi access point (AP) zones, task offloading must be handled opportunistically and "online." Our project focuses on the software implementation of this orchestration. By utilizing an Express.js backend API and a modern React.js frontend, we provide a visual, interactive system that tracks mobile user locations, evaluates available AP channels, and intelligently schedules tasks. The ultimate goal is to maximize the minimum residual energy ratio across all connected mobile devices, providing "equal opportunities" for both powerful laptops and restricted smartphones to offload tasks fairly without violating their respective Service Level Agreements (SLAs).

3. Literature Survey

3.1 Existing System

Considerable efforts have been made in recent years to address mobile application offloading. Systems like CloneCloud and MAUI aim to partition applications between mobile devices and a local cloudlet. However, these legacy systems primarily utilize offline, static partitioning mechanisms. They run simulations under fixed network characteristics to find an execution point and store it in a database. At runtime, they blindly pick a partition and offload it. This static approach fails entirely in real-world scenarios where mobile users travel between different venues (classrooms, libraries), causing dynamic fluctuations in Wi-Fi signal strength and Access Point bandwidth availability.

Furthermore, existing studies heavily focus on minimizing the absolute energy consumption or response time for a single, isolated device. They completely ignore the concept of "fair use" among a massive population of mobile users. In a real environment, careless task offloading results in a biased allocation where powerful devices (which have larger batteries and better connectivity) monopolize the local cloudlet's processing power, while restricted smartphones are unfairly forced to execute heavy tasks locally or use energy-draining 3G/4G networks, causing rapid battery death.

3.2 Proposed System

The "Offline Compute Grid" rectifies these flaws by proposing a dynamic, online location-aware task offloading system. In this proposed architecture, tasks arrive unpredictably in discrete time slots. The Node.js orchestration backend constructs a weighted bipartite matching graph in real-time. It maps incoming tasks (vertices on the left) to available computing facilities (local cloudlet via specific Wi-Fi APs, remote cloud via cellular, or the mobile device itself; vertices on the right).

The weights assigned to these edges are calculated using an advanced energy cost model that evaluates the "residual energy ratio" of the specific mobile device. The algorithm actively penalizes assigning tasks to devices with critically low batteries, forcing the system to offload their workloads to the local cloudlet. To make this complex, algorithmic backend accessible and manageable, the proposed system features a React-based frontend dashboard. This dashboard visually renders the network topology, tracks active task processing speeds, displays device statuses (Online, Busy, Idle), and provides real-time metrics on CPU and RAM utilization across the local cloudlet.

3.3 Feasibility Study

  • Technical Feasibility: The project is technically robust. Node.js is inherently asynchronous and event-driven, making it the perfect candidate for handling non-blocking bipartite matching algorithms and concurrent task requests from hundreds of mobile devices. The frontend utilizes React's Virtual DOM and Vite's rapid bundling, ensuring that the dashboard renders high-frequency telemetry updates (via Recharts) at a consistent 60 frames-per-second without crashing the browser.
  • Economic Feasibility: The two-tiered architecture is exceptionally cost-effective. By maximizing offloading to the local Wi-Fi cloudlet, the system avoids the exorbitant costs associated with 3G/4G cellular data plans. Furthermore, local cloudlets can be constructed using commodity hardware (repurposed PCs), circumventing expensive hourly billing from major cloud providers like AWS or Azure.
  • Operational Feasibility: The system abstracts the deep mathematical complexities of task-scheduling into a clean, modern user interface. Network administrators do not need to understand weighted bipartite graphs; they simply view device health, active tasks, and grid efficiency through intuitive Tailwind CSS-styled cards and visual indicators, making operational deployment highly feasible for university campuses or corporate offices.

3.4 Tools and Technologies

  • Frontend UI Library: React.js (v19): Utilized for its modular component architecture, allowing the isolation of complex dashboard elements (e.g., Task Managers, Device Detail views) into reusable, maintainable code blocks.
  • Build Engine: Vite (v8): Chosen over traditional bundlers like Webpack for its native ES-module support, providing near-instantaneous Hot Module Replacement (HMR) during development.
  • Styling Framework: Tailwind CSS (v4): A utility-first CSS framework that allows for rapid, inline styling, entirely removing the need for complex, cascading stylesheets and preventing CSS bloat.
  • Data Visualization: Recharts & Lucide React: Recharts is used to bind real-time algorithmic output (e.g., system throughput, CPU utilization) to SVG-based Area and Line charts. Lucide React provides crisp, scalable iconography.
  • Backend Runtime: Node.js & Express.js: The V8 JavaScript engine powers the backend API, routing task offloading requests and simulating the real-time execution of the location-aware scheduling algorithms.

3.5 Software & Hardware Requirements

  • Hardware Requirements:
    • Local Cloudlet (Master Node): A dedicated high-performance server (e.g., Intel Xeon / AMD EPYC, Min 16GB RAM) running the Node.js coordination environment and executing the offloaded tasks.
    • Mobile Devices (Worker/Client Nodes): Heterogeneous devices including Android smartphones, Apple iPads, and Windows Laptops equipped with 802.11g/n/ac Wi-Fi transceivers and 3G/4G cellular modems.
    • Network Infrastructure: A dense deployment of Wi-Fi Access Points (APs) distributed across the geographical area (e.g., a university campus) connected to a Gigabit local switch.
  • Software Requirements:
    • Operating System: Ubuntu Server 22.04 LTS (for the local cloudlet); Android/iOS for client devices.
    • Runtime Environment: Node.js version 20.x or higher.
    • Client Access: A modern HTML5, CSS3, and ES6 compliant web browser (Google Chrome, Mozilla Firefox, Microsoft Edge) to render the administrative dashboard.
